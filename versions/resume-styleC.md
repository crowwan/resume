## 강점 1 — 품질 자동화: 테스트를 "만드는" 것에서 "신뢰하게" 만드는 것으로

- **AI 변경 감지 E2E** — EC2의 Claude가 커밋 변경을 분석해 전체 대신 변경 관련 테스트만 자동 선별·실행(10분 주기, Teams 보고)하도록 만들어, 회귀를 같은 PR 안에서 조기에 잡도록 했습니다.
- **E2E 효율화** — Playwright 프레임워크를 주도 구축하고, 로그인 세션 공유로 전체 스위트 실행 시간을 **18분 → 11분(39%↓)**, 테스트별 로그인 셋업(약 60줄)을 공통 Page Object로 묶어 중복을 **93%↓** 줄였습니다.
- **격리 재현 환경** — 특정 커밋 시점의 클라이언트+서버를 Docker로 재현하고 qa/prod 데이터를 복제해, 환경 차이로 깨지던 디버깅·E2E를 안정적인 기반 위에 올렸습니다.
- *테스트를 더 짜기보다 "재현 가능한 환경"을 만드는 방향으로 신뢰성을 풀었습니다.* `DentBird Solutions`

## 강점 2 — 데스크톱 & 빌드 인프라: 0→1 설계와 릴리스 파이프라인

- **Electron 앱 0→1** — 웹↔로컬 CAM을 잇는 데스크톱 앱을 설계·릴리스(1개월 113커밋, v1.0.3)하고, 12개 CAM 소프트웨어의 좌표계 차이를 변환 매트릭스로 흡수했습니다.
- **Chrome LNA 선제 대응** — 웹→로컬 통신을 막는 규제에 우회 방안을 여러 갈래로 비교한 뒤 **장기 안정성 기준으로 Custom Protocol을 채택**했습니다(WebSocket은 향후 재차단 우려로 탈락).
- **빌드 파이프라인 재설계** — 담당자 PC·인프라팀에 의존하던 빌드를 self-hosted 파이프라인으로 옮겨 **빌드 시간을 20분 → 6분**(직접 비교)으로 줄이고, QA/PROD 채널을 분리했습니다. `DentBird Linker` `Electron 빌드 인프라`

## 강점 3 — 플랫폼 아키텍처: 모노레포·MFE·런타임 분리

- **런타임 환경 분리** — 환경변수를 빌드타임 주입에서 런타임 주입으로 전환해, 빌드 1개를 환경변수만 바꿔 dev·qa·prod에 배포하도록 만들고 **배포 후 핫픽스 반복을 해소**했습니다.
- **공통 모듈 통합(MFE)** — 4개 서비스 공통 기능을 iframe 런타임 통합으로 모듈화해 변경 시 **4곳 수정·배포 → 1곳**으로 좁혔습니다. 빌드타임↔iframe을 오가며 *"통합 전략은 조직·배포 제약의 함수"*임을 체득했습니다.
- **레거시 정리** — 모노레포 통합 시 TypeScript 에러 **688 → 0**, Facade 패턴으로 토큰 관리 코드 **200 → 33줄(85%↓)** 로 정리했습니다. `DentBird Solutions` `MFE`
