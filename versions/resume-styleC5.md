## 강점 1 — 품질 자동화: 테스트를 "만드는" 것에서 "신뢰하게" 만드는 것으로

- **AI 변경 감지 E2E** — 변경마다 전체 642개 E2E를 돌리던 것을, EC2의 Claude가 커밋 변경을 분석해 **관련 테스트 수 개만 골라 10분 주기로 자동 실행**하도록 바꿔, **회귀 확인까지 걸리던 시간을 전체 실행(약 18분) 대신 수 분 내로** 당겼습니다. 선별이 놓칠 회귀는 전체 스위트를 도는 일일 파이프라인으로 함께 보장했습니다.
- **E2E 효율화** — Playwright 프레임워크를 주도 구축하고, 로그인 세션 공유로 전체 스위트 실행 시간을 **18분 → 11분(39%↓)**, 테스트별로 반복되던 로그인 셋업 코드를 공통 Page Object 호출로 묶어 **60줄 → 4줄(93%↓)** 로 줄였습니다.
- **격리 재현 환경** — 특정 커밋 시점의 클라이언트+서버를 Docker로 재현하고 qa/prod 데이터를 복제해, 환경 차이로 깨지던 디버깅·E2E를 안정적인 기반 위에 올렸습니다.
- *테스트를 더 짜기보다 "재현 가능한 환경"을 만드는 방향으로 신뢰성을 풀었고, 이 격리·자동화 기반은 현재도 팀 E2E 파이프라인의 토대입니다.* `DentBird Solutions`

## 강점 2 — 데스크톱 · 빌드 인프라: 0→1 설계와 릴리스 파이프라인

- **Electron 앱 0→1** — 웹↔로컬 CAM을 잇는 데스크톱 앱을 **1개월 만에 v1.0.3까지 설계·릴리스**하고, 12개 CAM 소프트웨어의 좌표계 차이를 변환 매트릭스로 흡수해 어떤 CAM으로 내보내도 좌표가 어긋나지 않도록 했습니다.
- **Chrome LNA 선제 대응** — 웹→로컬 통신을 막는 규제에 우회 방안을 여러 갈래로 비교한 뒤 **장기 안정성 기준으로 Custom Protocol을 채택**했습니다(WebSocket은 향후 재차단 우려로 탈락).
- **빌드 파이프라인 재설계** — 담당자 PC·인프라팀에 의존하던 빌드를 self-hosted 파이프라인으로 옮겨 **빌드 시간을 20분 → 6분(70%↓, 직접 비교)** 으로 줄이고, QA/PROD 채널을 분리했습니다.
- *빠른 단기 해법보다 영구적 우회로를 택하고, 사람에게 묶여 있던 빌드를 파이프라인으로 옮긴 판단입니다.* `DentBird Linker` `Electron 빌드 인프라`

## 강점 3 — 플랫폼 아키텍처: 모노레포·공통 모듈 통합·런타임 분리

- **런타임 환경 분리** — 환경변수를 빌드타임 주입에서 런타임 주입으로 전환해, 빌드 1개를 환경변수만 바꿔 dev·qa·prod에 배포하도록 만들고 **배포 후 핫픽스 반복을 해소**했습니다.
- **공통 모듈 통합** — 4개 서비스 공통 기능을 **iframe 기반 런타임 통합**으로 모듈화해 변경 시 **4곳 수정·배포 → 1곳**으로 좁혔고, 현재도 4개 서비스 공통 모듈로 유지됩니다. (Module Federation은 별도 사내 서비스에 직접 적용해봤고, 이 건에선 초기 설정·소비처 부담을 이유로 iframe을 택했습니다.)
- **레거시 통합** — 분산돼 있던 레포를 모노레포로 합치며 누적된 **TypeScript 에러 688 → 0**, Facade 패턴으로 토큰 관리 코드 **200 → 33줄(85%↓)** 로 정리했습니다.
- *기술을 먼저 고르지 않고, 풀려는 문제와 조직·배포 제약에서 출발해 구조를 정했습니다.* `DentBird Solutions` `공통 모듈`

## 강점 4 — 제품 도메인: B2B 구독/결제와 정직한 기술 판단

- **구독제 전환 FE 전담** — 회사가 **일회성 크레딧 판매에서 반복 구독 매출로** 비즈니스 모델을 바꾸는 결제 경험을 프론트엔드에서 전담 설계·구축했고, 현재 **15개 국가 테넌트·다국어** 환경에서 운영됩니다.
- **결제 정합성** — 일할 계산·구독 취소/재개처럼 **금액이 어긋나기 쉬운 흐름**에서 발생하던 금액·상태 불일치를, 클라이언트 검증과 단일 상태 관리로 차단했습니다.
- **장애 격리** — 한 기능의 오류가 전체 페이지를 멈추던 구조를 ErrorBoundary로 기능 단위 격리해, **결제 일부의 실패가 화면 전체를 막지 않도록** 했습니다.
- *디자인 패턴·FSD를 적극 도입해본 뒤 "패턴은 검증된 공통 문제의 해법인데 우리가 풀려던 문제는 그게 아니었다"는 도입 기준을 얻었습니다.* `DentBird Account`
