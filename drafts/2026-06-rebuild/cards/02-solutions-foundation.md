**DentBird Solutions 플랫폼 토대** — 도메인 통합 라이브러리로 런타임 환경·격리 재현의 시작점을 깔고, 별도 레포의 분산 앱을 NX 모노레포로 이관·동기화
`2024.06 ~ 현재` · 도메인 통합 라이브러리 단독 / 모노레포 이관 owner / 런타임 환경 분리는 팀 공동(토대 제공)

여러 클라이언트 앱이 환경별로 URL과 도메인을 제각기 구성하던 구조였습니다. 먼저 도메인 파생을 한 곳으로 모으는 통합 라이브러리를 깔아, 팀의 런타임 환경 분리와 격리 재현 환경이 그 위에 쌓이도록 토대를 잡았습니다. 동시에 별도 레포에 흩어져 있던 앱들을 메인 모노레포로 끌어왔습니다.

▸ 기여
- 도메인 통합 라이브러리를 설계해 환경별로 흩어진 도메인·URL 구성을 한 곳으로 일원화 — 팀의 런타임 환경 분리·격리 재현 환경이 이 위에 얹히는 **시작점** 역할
- 별도 레포의 클라이언트 앱 2종과 공용 라이브러리 6종을 메인 NX 모노레포로 이관 *(Git Subtree Split으로 커밋 이력 보존 · 네임스페이스 충돌 리네임 · 이후 정기 동기화로 운영)*
- 산재한 다국어(i18n) 관리 스크립트를 중앙화 *(중복 업로드 스크립트 89줄 · 14개로 흩어진 패키지 스크립트 · 분산된 빌드 타겟 → 단일 스크립트 묶음)*
- NX 자동 타겟 추론이 일으키던 빌드 오류를 진단 — 불필요한 빌드 산출물 설정 제거로 **빌드 태스크 11개→9개**, 메모리 부족(OOM) 해결

▸ 판단·지속성
- 모노레포 도구는 새로 고르지 않고 기존 NX를 유지 — 다른 도구로 전환했을 때의 이득이 이관·재학습 비용을 넘지 못한다고 판단(백지 선택이 아닌 비용-편익 판단)
- 지속성: 통합 라이브러리가 깐 토대 위에서 격리 재현 환경이 운영 중이며, 모노레포는 원본 레포와 정기 동기화로 유지 중

`기술` TypeScript · NX 모노레포 · Git Subtree · i18n
