### 3D 렌더 품질 자동화 — 색·조명 정공법 재설계 + 픽셀 차분 기반 회귀 검출 (26.04~현재)
- 사내 엔진에서 Three.js로 옮긴 뷰어의 색·조명 차이를 **감마 보정값으로 덮던 상태를 SRGB 정공법으로 재설계** — 메인 스레드 WASM 디코더 폐기 등 약 1,420줄 제거

- 3개 앱이 공유하는 baseline을 단일 지표 세트로 운영(4 케이스 × 3 쌍 = 12 지표) → 정상은 평균 0.0, 색·조명 회귀 시 임곗값(2.0)을 넘긴 2.2865로 자동 차단
- 뷰어 mesh 변환을 단일 진입점으로 통합 — 사전 로딩·폴백·향후 경로가 모두 한 함수를 통과하도록 재설계(156개 명세·1,129개 테스트로 가드)

### Electron 빌드·배포·자동 업데이트 인프라 (24 초기 → 26 GitHub Actions 이관, 단독 운영)

- macOS 빌드 파이프라인 재설계 → **전체 33~39분 → 17~24분(56%↓), artifact 757MB → 334MB(56%↓), 업로드 114초 → 47초(59%↓)** *(PR 실측)*
- Windows 코드 서명용 전용 서명 에이전트를 물리 빌드머신에 직접 설치·에이전트 풀에 등록해 두 앱 파이프라인이 동시에 돌도록 구성 — 코드 서명 USB·인프라팀 의존 제거
- 서명을 빌드 과정 안에 포함 — 빌드 뒤 따로 서명하면 바이너리가 바뀌어 자동 업데이트가 깨진다는 걸 직접 부딪혀 학습한 결과
- **판단**: macOS 아키텍처를 Universal → arm64 → Intel로 11일 만에 3연속 번복(용량 2배 트레이드오프). blue-green 배포의 green 검증 자동화는 데스크톱 특성상 환경·빌드가 2배가 되는 운영비 대비 가치로 의도적 보류

### 관측성·ErrorBoundary 표준 정렬 (26.04~현재)
- 에러는 잡히지만 어디서 왜 났는지 추적이 안 되던 상태에서, **5개 앱의 ErrorBoundary를 팀 Datadog 관측 표준에 정렬하는 종합 계획서를 직접 작성·주도**(의사결정 7차 개정 + 5개 PR 분해)
- 3-layer ErrorBoundary 아키텍처(Root → Section → Feature) 설계, 5개 앱에 통합(4개 앱 완전 + 1개 부분)
- 한 에러 메시지로 뭉쳐 보이던 Export 실패 124건을, 커스텀 에러 클래스와 RUM 직렬화로 근본 원인까지 추적 가능하게(ADR)
- 최상위 Fallback에 디자인시스템·Hook·다국어 의존을 두지 않는 원칙 확립 — 안전망이 자기 의존성 때문에 죽지 않도록
- **판단**: 직접 추가한 에러 분류(7분류)가 특정 앱에 편향됐다고 보고, 팀 전체가 범용으로 쓸 표준이 필요하다 판단해 **자기 분류를 스스로 폐기하고 팀 표준에 정렬**

### Dentbird Account — B2B SaaS 구독·결제 FE (23.09~25.07)
- 일회성 크레딧 결제에서 반복 구독 매출로 전환하며, 글로벌 멀티테넌트 환경의 결제·권한 도메인 FE 전담 — 플랜 업그레이드·시트 구매·구독 취소/재개·쿠폰·결제수단·히스토리
- 기존 별도 결제 팝업 앱에 Stripe 결제 페이지 추가 — 부모↔팝업 origin 격리 구조를 활용해 결제 컨텍스트만 안전하게 주고받도록 연동
- 서버가 정상 응답으로 내려보내는 비즈니스 에러를 커스텀 에러로 받아 코드별로 분기 — 결제 정보를 못 받아도 결제 내역·구독 취소·뒤로가기 같은 핵심 흐름은 살아남도록 Fault Tolerance를 도메인 의존 관계 기준으로 설계
- 결제 상태 동기화의 무한 폴링 버그를 안전장치로 교정(기본 3초 간격 · 최대 20회 후 종료 · 언마운트 시 정리)
- 구독을 만든 사람이 운영자(Backoffice) 측 구독 회귀 가드까지 작성 — 구현부터 품질까지 한 사람이 종단 책임

### 공통 모듈 통합(MFE) + 기업 랜딩 풀스택 (MFE 24.11~25.04 · 랜딩 23.09~25.10)
