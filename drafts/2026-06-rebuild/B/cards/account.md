### Dentbird Account — B2B SaaS 구독·결제 FE
2023.09 ~ 2025.07 · 구독제 전환 FE 전담 설계·구현

일회성 크레딧 결제에서 반복 구독 매출로 비즈니스 모델을 전환하며, 글로벌 멀티테넌트 환경의 결제·권한 도메인 FE를 전담. 결제는 정확성이 곧 신뢰라, 기능 구현을 넘어 부분 실패에도 무너지지 않는 검증 구조까지 함께 설계.

- 플랜 업그레이드·시트 구매·구독 취소/재개·쿠폰·결제수단·결제 히스토리까지 구독 워크플로우 전체를 레거시 크레딧 결제와 공존시키며 전담 구현
- 기존 별도 결제 팝업 앱에 Stripe 결제 페이지를 추가, 부모↔팝업 origin 격리 구조 위에서 결제 컨텍스트만 안전하게 주고받도록 연동
- HTTP 200으로 내려오는 서버의 비즈니스 에러를 커스텀 에러로 받아 코드별 분기 — 결제 정보를 못 받아도 내역 조회·구독 취소·뒤로가기는 살아남도록 Fault Tolerance를 도메인 의존 관계 기준으로 설계
- 결제 상태 동기화의 무한 폴링을 폴링 안전장치로 교정 — 기본 3초 간격·최대 20회 후 종료·언마운트 시 정리
- 구독을 만든 사람이 운영자(Backoffice) 측 구독 회귀 가드까지 작성 — 구현부터 품질까지 한 사람이 지는 종단 책임
- FSD·컴포넌트 패턴을 처음 본격 도입하며 과적용을 경험하고, 폴더 합의 비용·팀원별 해석 분기를 겪은 끝에 "기술 도입은 일관성이 아니라 우선순위 높은 문제부터"라는 기준으로 수렴 — 이후 모노레포 이관 뒤에도 에러 처리·도메인 분리 골격은 그대로 정착

`기술` React · TypeScript · react-query · Stripe · FSD · ErrorBoundary · Playwright(E2E)
