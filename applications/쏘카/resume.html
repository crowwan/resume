자기소개

AI로 빠르게 개발하고, 그 변화를 자동화된 검증으로 안전하게 관리하는 프론트엔드 개발자입니다.

2023년 9월부터 AI 기반 치과 SaaS Dentbird의 프론트엔드를 맡아 구독·결제, 3D 뷰어, 외부 CAM 연동처럼 외부 시스템과 실행환경에 맞물린 화면을 주도적으로 개발·운영해 왔습니다. 웹과 로컬 소프트웨어를 잇는 Electron 연동 앱(Linker)은 설계부터 운영까지 혼자 맡았습니다. 브라우저 정책에 막힌 로컬 통신을 Custom Protocol로 재설계했고, CAM 없이 연동을 검증하는 Mock Server와 Windows 전용 CAM 소프트웨어를 Mac에서 그대로 재현하는 원격 검증 도구도 직접 만들어 팀에서 쓰고 있습니다.

AI 에이전트는 코드 자동완성이 아니라 검증 단계에 씁니다. 커밋마다 바뀐 코드를 분석해 연관된 테스트만 골라 격리 환경에서 실행하고, 실패를 실제 회귀와 테스트 코드 문제로 1차 분류하는 워크플로우를 만들었습니다. 한계도 확인했습니다. 명세 검증을 전량 AI로 자동화하려다 실행마다 결과가 달라져 되돌렸고, AI가 만든 테스트를 AI가 평가하면 결함을 놓친다는 것을 mutation testing으로 확인한 뒤 검증을 통과해 나간 결함부터 측정하는 쪽으로 바꿨습니다.

좋은 개발은 팀이 같은 방향을 공유할 때 나온다고 보아, 성과뿐 아니라 되돌린 결정과 한계까지 정직하게 남기려 합니다.

경력

이마고웍스 (ImagoWorks) | 프론트엔드 개발자 | Dentbird 1 Team | 2023.09 ~ 현재

AI 기반 치과 CAD/CAM SaaS인 Dentbird의 프론트엔드를 맡아, 복잡한 화면 구현부터 모노레포 통합·런타임 환경 분리·품질 자동화 같은 플랫폼 기술 결정까지 담당해 왔습니다.

  • 격리 재현 환경과 AI 변경 감지 기반 품질 자동화·E2E 인프라 구축, 회귀 측정(CFR) 대시보드 운영

  • 구독·결제 도메인 프론트엔드 전담, FSD·선언적 에러 처리 아키텍처 설계
  • 5개 앱 에러 관측·복원력 표준화(Datadog), 3D 렌더 정합 재설계·시각 회귀 테스트
  • 여러 클라이언트 앱·라이브러리를 NX 모노레포로 통합·환경·도메인 구성 일원화
  • 기업 랜딩 v3 풀스택 단독 리뉴얼 — 화면부터 서버 API까지 성능·SEO·타입세이프 i18n

주요 프로젝트

AI 변경 감지와 회귀 측정(CFR)

AI로 코드 변경 속도가 빨라진 만큼 회귀도 늘어난 팀에서, AI를 “어떤 테스트가 이 변경에 필요한가”라는 판단 단계에 결합하고, 그 판단이 놓치는 것까지 측정했습니다.

  • 커밋 시점 클라이언트·서버·DB를 하나의 컨테이너로 통합해 결정론적 격리 재현 환경 구성
  • 커밋 변경을 분석해 연관 QA 테스트 케이스만 자동 선별·실행하고, 실패를 실제 회귀와 테스트 코드 문제로 1차 분류해 Teams로 보고
  • 명세 검증을 AI로 전량 자동화하려다 비결정성과 토큰 비용의 한계를 확인하고 격리 재현 위 E2E로 되돌림
  • AI가 만든 테스트를 AI가 평가하는 구조의 맹점을 mutation testing으로 측정(정성 평가 A급 코어 라이브러리가 57%), 이후 배포마다 검증을 통과해 나간 결함을 추적하는 CFR 대시보드를 화면과 API까지 직접 구축해 팀에서 운영
  • 한계도 함께 설계 — AI 리뷰가 오히려 통과시킨 잘못된 테스트가 회귀를 굳힌 사례를 직접 바로잡고, 기획 의도가 코드·테스트가 아닌 티켓 코멘트에만 있던 원인까지 확인

웹·로컬 CAM 연동 Electron 앱 (Dentbird Linker)

웹에서 만든 보철 케이스를 사용자 PC의 CAM 소프트웨어로 전달하는 사내 연동 앱을, 설계부터 운영까지 단독으로 맡았습니다.

  • Chrome LNA 정책으로 막힌 로컬 서버 통신을, 구현 속도가 아닌 장기 안정성 기준의 대안 비교 끝에 Custom Protocol 중간 레이어로 재설계 (WebSocket은 곧 같은 정책 적용 대상이라 제외)
  • 좌표계·전달 방식이 제각각인 외부 CAM 12종을 단일 변환·연동 인터페이스로 통합, 명세 없던 연동을 특성화 테스트로 고정한 뒤 재구현
  • 설치 감지는 정확도를 높이는 대신 틀려도 사용자가 막히지 않도록 비차단 안내로 통일하고, 감지 판정 자체를 없애는 다음 단계를 기획·QA와 합의
  • Windows 전용 CAM을 Mac에서 실제 전송과 동일하게 재현하는 원격 검증 도구를 직접 만들어 팀 스킬로 등록 — 조건을 하나씩만 바꿔 대조해 형상 오류의 원인을 규명하고, 다른 사례는 벤더 실행 인자 제약임을 확인해 결함이 아님을 확정
  • CAM 12종 없이 성공·지연·타임아웃·부분 실패를 재현하는 Mock Server를 직접 만들어 검증하고, 운영 중 발생한 정체불명 오류는 처음 의심한 원인이 아님을 Datadog 로그로 확인한 뒤 실제 원인 확정

B2B 구독·결제 시스템 프론트엔드

일회성 크레딧에서 반복 구독으로 전환하는 시점에 글로벌 멀티테넌트 결제·권한 프론트엔드를 전담하고, 외부 결제 시스템과 맞물린 실패를 화면이 감당하도록 구조를 나눴습니다.

  • 플랜 업그레이드·시트 구매·구독 취소·재개·쿠폰·결제수단·결제 히스토리까지 구독 워크플로우 전체를 구현
  • 결제 상태를 서버·Stripe 동기화 기준으로 두고, 무한 반복 방지 폴링·origin 격리된 결제 팝업으로 외부 연동 복원력 확보
  • 모든 에러를 unknown으로 일괄 처리하던 것을 예측 가능/불가능으로 구분 — 비즈니스 에러는 코드별 분기, 시스템 실패는 ErrorBoundary로 격리해 한 기능의 실패가 전체 페이지를 멈추지 않게 함
  • 이 문제의식을 이후 5개 앱 관측·복원력 표준화로 확장, 한 줄로 뭉쳐 보이던 실패 124건을 원인별로 추적 가능하게 직렬화

케이스 목록 썸네일 로딩 최적화

가장 자주 보는 화면에서 지연 로딩·요청 배치로 “N장=N요청” 구조를 해소하고, 재마운트마다 캐시가 소실되던 무한 재요청을 공유 캐시로 근절했습니다.

  • “N장 = 네트워크 N요청”이 되기 쉬운 썸네일을 IntersectionObserver로 보일 때만 로드하고, 동시에 들어온 요청을 모아 한 번에 배치 요청으로 처리
  • 운영 중 발생한 무한 재요청을 재시도 제한으로 억제하는 대신, 재마운트마다 훅·캐시가 소실되는 구조를 진단해 캐시를 공유 스코프로 끌어올리고 성공뿐 아니라 실패도 캐시해 근본 해결, 회귀 테스트로 고정
