# 파생본(JD별) 작성 체크리스트

`applications/<회사>/` 파생본을 만들 때 따르는 룰입니다.
**마스터(루트 `resume.md`·`portfolio.md`)에서 JD에 맞게 선별·압축·재배치**하며, 마스터에 있는 사실만 씁니다.

> 도출 근거: 오늘의집 서류 탈락(2026-06) 분석 — ① 이력서 파생이 압축되긴커녕 마스터보다 길어짐, ② 포트폴리오 5장 선별이 인프라 4 : 제품 1로 "인프라 FE" 인상을 오히려 강화, ③ "보완하고 싶은 영역" 자백이 서류 첫 컷에서 필수 미달 신호로 읽힘.

---

## 핵심 원칙

- **마스터 = 풀 카탈로그 / 파생 = 선별·압축·재배치.** 파생에서 새 사실·수치 발명 금지.
- 귀속 경계 유지 — 타팀/hckim 웹인프라·Account 제품 수치 등 인용 금지 (메모리 `resume-attribution-boundary`).

---

## 0. 시작 전
- [ ] `applications/<회사>/research.md` 작성/확인 — JD **필수·자격·우대** 추출
- [ ] 지원 직무의 **핵심 책임**(직무 본문)과 **우대**(있으면 좋음)를 구분

## 1. JD 매핑
- [ ] 필수/자격/우대를 표로 만들어 본인 카드와 매핑
- [ ] 미달 항목 식별 → **인접 근거로 연결**(과장 금지), 없으면 **성장 서사로 정직하게**
- [ ] ★ **"보완하고 싶은 영역" 자백 섹션은 서류 버전에서 최소화/제거** (면접 대비용으로만 보관)

## 2. 포트폴리오 카드 선별
- [ ] JD **핵심 책임**(우대 아님)에 닿는 카드 우선
- [ ] ★ **사용자 대면/제품 카드 최소 1~2장 의무 확보** — 인프라·테스트·빌드 일색 금지
- [ ] 5장 내외로 압축 (마스터 11장 전부 넣지 않기)

## 3. 순서·대표작
- [ ] **1번 카드 = 그 JD에서 제품·사용자 임팩트가 가장 큰 것** (JD마다 1번이 달라짐)
- [ ] 인프라·테스트·빌드 카드는 뒤로
- [ ] 첫 화면 인상이 "제품 만드는 FE"인지 확인 (인프라 FE로 읽히지 않게)

## 4. 톤
- [ ] 각 카드 첫 2줄은 **성과 먼저**, 회고·한계는 뒤 (삭제 X — 순서만)
- [ ] 주도성 서술("내가 주도")을 "흡수/수렴" 같은 수동적 결말 **앞에** 배치

## 5. 이력서 압축
- [ ] ★ 프로젝트 **대표 3~4개 + 나머지 한 줄** (9개 평면 나열 금지)
- [ ] 대표작이 JD 핵심 책임과 정렬되는지

## 6. 최종 점검
- [ ] 마스터와 수치·기간·명칭 일치
- [ ] 귀속 경계 위반 0 / 발명된 수치 0
- [ ] `EVALUATION-RUBRIC.md` 통과까지 개선
