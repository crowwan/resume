## 1. JD 핵심 요구

**타깃 직무: 프론트엔드 엔지니어 (경력 2년 이상 또는 그에 준하는 역량)**
- 도메인: 여성 패션 C2C에서 출발 → **종합 스타일/버티컬 커머스로 확장 중**. 단일 화면이 아니라 **여러 표면(surface)을 넘나드는** 직무.

**주요 업무**
- PC/모바일 웹사이트 및 **네이티브 앱 내 웹뷰** 운영
- 사용자 서비스 경험 개선
- **마켓 관리 어드민**(셀러/마켓용) 웹사이트 운영
- **서비스 운영 어드민**(내부 운영용) 웹사이트 운영
- 신규 사업 서비스 포함 FE 전반
- → 핵심: **B2C(웹+웹뷰) + B2B(셀러 어드민) + 내부운영(운영 어드민)** 3종 표면을 한 직무가 폭넓게 커버.

**자격 요건**
- 개발 경력 **2년 이상 또는 그에 준하는 역량**
- TypeScript/JavaScript 및 **브라우저 동작에 대한 깊은 이해**
- React, Vue.js 등 모던 웹 프레임워크 능숙
- **코드 안정성과 확장성의 균형** 유지 능력
- 주도적 문제 정의 및 해결책 도출

**우대 사항**
- ★ **"AI 도구를 적극적으로 활용해 문제 해결 속도를 높여본 분"** — 공고에 명시. 당근·오늘의집보다 더 직접적으로 AI 활용을 명문화.
- 조직문화 공감 및 팀 성과 기여 의지

**명시 기술스택(공고 원문)**: TypeScript · React · React Native · Next.js · Vue.js · TanStack Query · **Jotai · Zustand** · styled-components · Webpack · Vite · **Re.pack** · GitHub Actions

> 스택에서 읽히는 신호:
> - **React+Next.js**가 웹 본진, **React Native+Re.pack**이 앱/웹뷰 본진 (Re.pack = RN을 Webpack/Module Federation으로 번들 → 코드푸시·동적 모듈 가능성).
> - 클라 상태 **Jotai+Zustand 병존** → 용도별 분리 또는 레거시/신규 혼재. 면접 역질문 후보("왜 둘 다?").
> - 서버 상태 **TanStack Query** 표준.
> - **Vue.js 잔존** → 일부(특히 어드민) 레거시가 Vue일 가능성.
> - 번들러 Webpack→Vite 전환 흐름 추정.

## 2. 회사가 푸는 문제 · 일하는 방식

- **목적조직 스쿼드 + 직군 챕터** (확인): 스쿼드 = 전 직군이 모인 애자일 목적조직("작은 스타트업처럼"), FE 1~3명. 챕터 = 같은 직군 모임으로 스쿼드에서 풀기 어려운 기술 부채·"회색 지대" FE 영역을 TF로 모아 주도 처리. "스쿼드=제품 목표, 챕터=기술 건강성"의 2축(토스·당근 모델과 동형).
- ★ **짝꿍 스쿼드 리뷰 게이트** (확인, 특징적): 비슷한 도메인 스쿼드끼리 1:1 매핑해 서로의 **필수 리뷰어** 지정. 피처 배포 전 짝꿍 스쿼드 필수 리뷰어의 리뷰+동의가 있어야 배포 가능. → **"리뷰를 통과해야 배포"가 제도화**됨. 안정성·검증 강조 지원자와 결이 맞음.
- ★ **웹뷰 확장에 투자 중** (확인): 앱 업데이트(스토어 심사) 없이 화면 갱신 → 빠른 실험에 웹뷰가 최적이라 판단. "웹뷰 확장 기반"을 만드는 중. JD "웹뷰 운영" + 스택 `Re.pack`과 연결. → **"빠르게 바뀌는 코드를 안전하게"** 라는 본인 포지셔닝과 정합성 높음.
- **빠른 배포·피드백 문화** (확인): "최대한 빠르게 배포하고 피드백 기반으로 속도감 있게 개선".
- **AI 도구 활용** (부분 확인): 공고 우대에 명시 → 회사 차원 긍정/장려 신호. 단 사내 구체 도구·정착도는 미확인.

## 3. 도메인 · 규모 (확인)

- **버티컬 커머스 최초 MAU 1,000만 돌파**(2025-06, ~1,005만). 와이즈앱 기준 버티컬 커머스 1위.
- 거래액 약 2조원(2024), 앱 누적 다운로드 5,000만(2024 말).
- **입점 마켓 약 10만 개**(업계 최대) → 셀러/어드민 트래픽도 상당.
- 셀러 생태계: 사입/물류/CS/마케팅 대행 **에이블리 파트너스** + 오픈마켓형 **에이블리 셀러스**. JD "마켓 관리 어드민"은 이 10만 마켓 셀러용 도구.
- AI 기반 개인화 추천 + 전 상품 무료배송이 차별점.

## 5. 지원자 매칭 (초안 메모 — 파생 작성 시 확정)

- ★ **포지셔닝 정면 일치** — 에이블리 "웹뷰로 빠르게 배포 + 짝꿍 스쿼드 필수 리뷰 게이트" ↔ 본인 축 "빠르게 바뀌는 코드를 검증·가드로 안전하게"(메모리 `resume-positioning-safe-change`). 당근(속도 일변도)보다 **검증 강조가 오히려 유리**.
- ★ **AI 우대 직격** — 공고 우대 "AI로 속도 높여본 분" ↔ 변경 감지·테스트 선별(검증형 AI 활용, 메모리 `resume-ai-usage`). FE 지원자 중 희소 차별. ※ 멀티에이전트는 강점으로 쓰지 말 것(메모리 룰).
- ★ **여러 표면 운영** — 웹/웹뷰/어드민 멀티 surface ↔ MFE·same-origin iframe 모듈화, 여러 클라이언트 앱 경험과 매핑.
- **브라우저 동작 깊은 이해**(자격) ↔ Linker의 Chrome LNA·Custom Protocol·실행환경 정책 재설계. 우대 직격은 아니나 "브라우저 깊은 이해" 자격과 직접 연결.
- **안정성·확장성 균형**(자격) ↔ 회고 단골 주제(MFE 3번 재설계·NX 유지 비용편익·공유캐시 실용 선택).
- **상태관리·번들러** — TanStack Query·Zustand·Webpack·Vite 실무 경험(기술스택) → 명시 스택과 직접 겹침.

**약한 영역(정직)**: C2C 패션 커머스 도메인 미경험, 인앱 웹뷰 실무 미경험(Electron/RN 웹뷰 아님 → Re.pack은 미경험이나 "실행환경 제약 다룬 경험"으로 인접 연결), Jotai 미사용.

## 6. 이력서 강조 전략 (초안)

- 첫 축 **"빠른 웹뷰 배포 ↔ 검증 게이트"의 정합** — 에이블리가 제도화한 짝꿍 스쿼드 리뷰·웹뷰 확장과 본인 "안전한 빠른 개발" 축이 정면으로 맞음. 무리한 리프레이밍 불필요.
- 둘째 축 **AI를 판단 단계에 결합**(변경 감지·테스트 선별) — 공고 우대 직격.
- 셋째 축 **여러 표면 + 브라우저 깊은 이해**(MFE·iframe 모듈화 / LNA·Custom Protocol).
- 약한 영역(커머스 도메인·웹뷰 실무·Jotai)은 **수치 지어내지 말고 성장 서사로 정직하게**.
- ※ 파생 작성 시 케이스 큐레이션은 **웹뷰·여러 표면·AI·검증게이트** 키워드 기준 → 당근과 선별이 약간 달라짐(다음 작업).
