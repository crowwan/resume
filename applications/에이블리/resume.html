자기소개

AI로 빠르게 개발하면서, 그 변화를 검증으로 안전하게 받치는 프론트엔드 개발자입니다.

2023년 9월부터 AI 기반 치과 SaaS Dentbird의 프론트엔드를 맡아 구독·결제, 3D 뷰어, 외부 CAM 연동, 데스크톱 앱까지 외부 의존이 많은 여러 클라이언트 화면을 주도적으로 개발·운영해 왔습니다. 웹과 로컬 소프트웨어를 잇는 Electron 연동 앱(Linker)은 혼자 설계·운영하며, 브라우저 정책에 막힌 로컬 통신을 Custom Protocol로 재설계하는 등 브라우저·실행환경의 제약을 직접 다뤘습니다.

AI는 코드 자동완성을 넘어 변경 감지·테스트 선별 같은 판단 단계에 결합해, 빠르게 바뀌는 코드도 안전하게 검증하는 워크플로우를 직접 만들었습니다. 재현되지 않는 문제는 끝까지 파고들어 근본 원인을 고칩니다. 기술 도입은 트레이드오프를 정량적으로 따져 가치가 분명할 때 선택하고, 만든 뒤에도 실제로 효과가 있었는지 되짚어 의미가 없으면 인정하고 방향을 바꾸는 방식으로 일합니다.

좋은 개발은 팀이 같은 방향을 공유할 때 나온다고 보아, 성과뿐 아니라 되돌린 결정과 한계까지 정직하게 남기려 합니다.

주요 프로젝트

케이스 목록 썸네일 로딩 최적화

가장 자주 보는 케이스 목록 화면에서 지연 로딩·요청 배치로 “N장=N요청” 구조를 해소하고, 재마운트마다 캐시가 소실되던 무한 재요청을 공유 캐시로 근절했습니다.

  • “N장 = 네트워크 N요청”이 되기 쉬운 썸네일을 IntersectionObserver로 보일 때만 로드하고, 동시에 들어온 요청을 모아 한 번에 배치 요청으로 처리
  • 운영 중 발생한 무한 재요청을 재시도로 억제하는 대신, 재마운트마다 훅·캐시가 소실되는 구조를 진단해 캐시를 공유 스코프로 끌어올리고 성공뿐 아니라 실패도 캐시해 근본 해결, 회귀 테스트로 고정

AI 변경 감지와 격리 재현 테스트 환경

AI를 코드 자동완성이 아니라 “어떤 테스트가 이 변경에 필요한가”라는 판단 단계에 결합한 워크플로우를 구축했습니다.

  • 커밋 시점 클라이언트·서버·DB를 하나의 컨테이너로 통합해 결정론적 격리 재현 환경 구성
  • EC2에서 Claude를 상시 구동해 커밋 diff를 분석, 연관 QA 테스트 케이스만 자동 선별·실행하고 실패를 회귀와 테스트 코드 문제로 1차 분류해 Teams로 보고(10분 주기 크론잡)
  • 만성 실패하던 격리 daily를 원인별로 분리 진단 — 결제 경로 실패 약 28건을 0으로, S3 다운로드 DNS 포화를 대조 실행으로 확정해 공유 캐시로 해소
  • 한계도 함께 설계 — AI 리뷰가 오히려 통과시킨 잘못된 테스트가 회귀를 굳힌 사례를 직접 바로잡고, AI 판단의 맥락 부재 위험까지 고려

웹·로컬 CAM 연동 Electron 앱 (Dentbird Linker)

웹 보철 케이스를 사용자 PC의 CAM 소프트웨어로 전달하는 사내 연동 앱을 단독 설계·운영하며, 좌표계·전달 방식이 제각각인 외부 CAM 12종을 단일 연동 인터페이스로 통합했습니다.

  • Chrome LNA 정책으로 막힌 로컬 서버 통신을, 장기 안정성 기준의 대안 비교 끝에 Custom Protocol 중간 레이어로 재설계
  • 좌표계·전달 방식이 제각각인 외부 CAM 12종을 단일 변환·연동 인터페이스로 통합, 명세 없던 연동을 특성화 테스트로 고정 후 재구현
  • 설치 감지는 틀려도 사용자가 막히지 않게 비차단 안내로 통일, CAM 없이 시나리오를 재현하는 Mock Server로 검증
  • Batch의 Electron→웹뷰 전환에서 웹뷰 구조를 이해하고 설계에 참여, 3D 엔진이 웹뷰 환경에서 동작하도록 구현(전환은 팀 주도)

B2B 구독·결제 시스템 프론트엔드

일회성 크레딧에서 반복 구독으로 전환하는 시점에 글로벌 멀티테넌트 결제·권한 프론트엔드를 전담하고, 모든 에러를 unknown으로 처리하던 구조를 예측 가능/불가능으로 나눠 한 기능의 실패가 전체 페이지를 멈추지 않도록 개선했습니다.

  • 플랜 업그레이드·시트 구매·구독 취소·재개·쿠폰·결제수단·결제 히스토리까지 구독 워크플로우 전체를 구현
  • 결제 상태를 서버·Stripe 동기화 기준으로 두고, 무한 반복 방지 폴링·origin 격리된 결제 팝업으로 외부 연동 복원력 확보
  • 모든 에러를 unknown으로 일괄 처리하던 것을 예측 가능/불가능으로 구분 — 비즈니스 에러는 코드별 분기, 시스템 실패는 ErrorBoundary로 격리
