## 1. JD 핵심 요구

**필수 (통합 공고 공통)**: CS 전공/동등 지식 — **자료구조·알고리즘 깊이** 강조(CTO도 "기초 충실"이 시니어 판단 1순위), 새 기술 빠른 학습, 신속한 디버깅.
**필수 (FE 전용)**: **2년+ FE 경험**(지원자 충족), **Modern JS(ES6+) 깊은 이해 + TypeScript**, **React 기반**.
**우대**: CS 석/박사, 병역특례.
**책임 (FE)**: **데스크(상담사용 데스크톱 앱) 개발**, **대용량 데이터 시각화**, **크로스브라우징**, **디자인 시스템 운영**.
**도메인**: AI 메신저/CRM 고객 상담, B2B SaaS, 실시간 채팅, 글로벌 확장, CS 자동화.

## 2. 회사가 푸는 문제 · 일하는 방식

**푸는 문제**: B2B SaaS 올인원 고객 커뮤니케이션 — 실시간 채팅 + CRM + 마케팅 + AI 상담 에이전트(ALF). 핵심 화면 **"데스크"**(상담사 앱)는 실시간 채팅·**스프레드시트형 CRM**·통계·필터링 에디터 등 **대용량 데이터·복잡 UI**를 한 화면에서 처리. 방향성은 **AI 에이전트(ALF V2)·AI 마케팅**으로 이동 중.

**일하는 방식 / 문화**
- 엔지니어 핵심가치: Customer Driven / **Deep Roots & Clear Solutions** / Small Talk·Big Results / Move Fast & Adapt Quickly
- **시니어리티 = 연차 아님**. "고객 문제를 **엔지니어링 문제로 얼마나 잘 정의**하는가"
- 철학: **"블록 하나하나는 신중하게 설계, 시스템 쌓는 속도는 빠르게"**
- 2주마다 전 엔지니어 엔지니어링 세션(200회+), tech.channel.io·DevRel → **DX 중시**
- "룰이 없는 게 룰", 단일 제품 집중
- 팀: Core(웹·백·모바일·AI·데브옵스) + Feature(ALF·Meet·AI마케팅)
- CTO: 스택보다 **"이건 왜 이렇게 되어 있지?"를 던지고 깊게 파는 태도**, AI 시대엔 "무엇을 구현할지"가 "어떻게"보다 중요

## 3. FE 기술 스택 · 관심사
- 코어: **React + Redux + Redux-Saga**
- 데스크톱: **데스크 앱**(웹/Windows/OSX) + 멀티 환경 일관 동작(크로스브라우징)
- **모노레포 (핵심 관심사)**: **yarn workspace** 기반. **Nx/Turborepo/Lerna 의도적 미채택** — 이유: TS Project References + incremental build로 충분. circular dependency 자동 감지, 패키지 생성 3초 자동화 등 빌드/생산성 자동화에 직접 투자. 배경: 멀티 repo 컴포넌트 중복 → 공유 패키지 → 일관성 붕괴 → 모노레포 통합(전형적 성장 서사)
- 에디터: ProseMirror 기반 자체 toolkit(오픈소스)
- 반복 키워드: 디자인 시스템 운영, 대용량 데이터 시각화, 크로스브라우징

## 4. 지원자 매칭

1. **모노레포 통합 (최강, 거의 1:1)** — 지원자 NX 통합 ↔ 채널톡 멀티 repo 중복→통합 동일 문제. 단 채널톡은 **Nx 의도적 배제(yarn workspace)** → 지원자가 NX를 왜 택했는지/트레이드오프를 말할 수 있으면 그들의 "왜 이렇게?" 문화와 공명. (★ 발명 금지: 실제 선택 근거는 본인만 앎)
2. **MFE(iframe·MF) ↔ 데스크/플러그인/디자인시스템 패키지 분리**
3. **Electron 0→1 ↔ 데스크 앱(Win/OSX)+크로스브라우징** + 빌드 20→6분 = 그들 생산성 자동화 가치와 동일 결
4. **품질 자동화(E2E·Docker 격리·AI 변경감지) ↔ DX + AI 자동화 방향**
5. **B2B SaaS 구독/결제 + 글로벌 ↔ 동일 도메인**

## 5. 이력서 강조 전략

채널톡은 "고객 문제를 엔지니어링 문제로 정의"와 트레이드오프 설명력을 본다 → 기존 자산을 **"문제 정의→대안→왜 버렸나→결과→한계"의 4축 서사로 재배치**. **모노레포 카드를 톱**에 두되, 채널톡이 Nx를 배제하고 yarn workspace+TS Project References를 택한 사실을 의식해 "나는 NX를 이런 트레이드오프로 택했다"는 판단 근거를 드러내면 도구 일치가 아닌 **판단력 일치**로 어필. Electron+빌드 20→6분, 품질 자동화를 "데스크 앱·DX·AI"라는 현재 관심사에 정렬. 문화코드("Move Fast", "블록은 신중·시스템은 빠르게")에 맞춰 **속도+신중한 설계를 보여준 성장 서사**(빠른 도입→한계→재설계) 전면 배치.

> ★ 발명 금지: "왜 NX였는가"의 실제 트레이드오프 근거는 본인만 안다. 이력서/면접 전 본인 확인 필요.
