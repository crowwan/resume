## 프로젝트

### 1. 플랫폼 아키텍처 — 모노레포 통합 & Micro Frontend

4개 서비스(cloud·crown·modeler·milling)가 공유하는 공통 기능 4개가, 하나 바뀔 때마다 **각 서비스에 같은 수정을 반복하고 전부 배포**해야 하는 비용이 문제였습니다. 이걸 푸는 통합 전략을 여러 번 다시 골랐습니다.

- 먼저 컴포넌트를 **라이브러리로 배포**해봤지만, 각 서비스가 버전을 올리고 다시 배포해야 해서 풀려던 문제가 그대로 남았습니다. 그래서 런타임 통합으로 방향을 틀어 **타입 안전한 same-origin postMessage 통합** 를 택했습니다.
- **Module Federation**은 직접 도입해본 경험상 초기 설정이 복잡하고 모노레포 밖 소비처에서 설정 부담이 커서 이 건에선 제외했습니다 — 몰라서가 아니라 써보고 트레이드오프로 뺀 판단이며, 다른 서비스에는 별도로 적용했습니다.
- 분산된 앱을 **NX 모노레포로 통합**한 뒤에는 빌드타임 통합으로 옮겼다가, **통합 배포가 실제로는 잘 이뤄지지 않고 사내 배포 프로세스가 짧은 주기 배포를 어렵게 바뀌자 다시 iframe 런타임 통합으로 회귀**했습니다. 이번엔 모듈별 도메인 대신 same-origin으로 서빙해 CORS·인증 공유를 단순화했습니다.
- **판단**: 정답 기술이 따로 있는 게 아니라, 조직·배포 제약에 맞춰 라이브러리 → iframe → 빌드타임 → iframe으로 재선택한 과정 자체가 결론이었습니다. 도구(NX)를 고른 근거와 탈락한 대안의 이유까지 설명할 수 있게 트레이드오프를 남깁니다.

### 2. 데스크톱 앱 & 3D 뷰어

사용자 현장에서 도는 Electron 데스크톱 앱을 설계·구축하고 그 빌드·배포까지 책임졌습니다.

- 또 다른 데스크톱 앱(크라운 배치 처리)에서 **VTK.js 기반 3D Viewer**의 마우스 인터랙션을 Windows/Mac에서 일관되게 통일했습니다.
- 3D 렌더링 안정성을 관측 가능하게 만들기 위해 **WASM 메모리 모니터링·Crash Reporter·Datadog RUM**으로 데스크톱 런타임을 계측했습니다.
- 웹↔로컬 통신을 막는 Chrome **LNA 정책**에 대응해 HTTPS 로컬 서버·WebSocket·Custom Protocol 등을 비교하고, **장기 안정성 기준으로 Custom Protocol을 채택**했습니다. 이질적인 외부 CAM들의 좌표계·전달 방식 차이를 하나의 변환·연동 인터페이스로 추상화했습니다.
- 빌드가 담당자 PC·인프라팀(코드사인)에 묶여 있던 구조를 self-hosted 빌드머신으로 재설계하고, **Azure Pipelines → GitHub Actions 이관을 주도**해 빌드를 20분대 → 6분으로 줄였습니다 *(직접 비교 · 팀 작업, 본인 최다 기여)*. 자동 업데이트 라이브러리 내부까지 분석해 버그·인증을 패치했습니다.
- **판단**: WebSocket은 구현이 빠르나 곧 LNA 적용 대상이라 재차단 우려로 탈락 → 장기 안정성을 보고 Custom Protocol 채택. 명확한 스펙이 없던 기능은 특성화 테스트로 기존 동작을 고정하고 구현으로 통과시켜 회귀를 보장했습니다.

### 3. 품질 자동화 — 격리 재현 & AI 변경 감지

환경 차이로 깨지던 디버깅·E2E를 안정화하기 위해, "격리하기 쉬운 환경"을 먼저 깔고 그 위에 자동화를 확장했습니다.

- 특정 커밋 시점의 클라이언트+서버를 **Docker로 격리 재현**하는 환경을 주도 구축해, 환경 차이로 깨지던 디버깅·E2E를 안정화했습니다.
- 흩어진 Playwright E2E를 모노레포로 통합하고, 반복되던 로그인 셋업을 **공통 Page Object 호출로 대체**, 세션 공유로 중복을 제거했습니다.
- **AI 변경 감지 E2E**: EC2에 Claude를 띄워 커밋 변경을 분석하고, 전체를 매번 돌리는 대신 **관련 E2E만 선별·실행**해 결과를 Teams로 보고하도록 구축했습니다.
- **판단**: AI 변경 감지는 운영 한계(보안·안정성)까지 겪고 재편 중입니다. 자동화는 화려한 도구를 먼저 얹기보다, 재현 가능한 토대를 깐 뒤 그 위에 쌓는다는 순서를 지킵니다.

### 4. B2B SaaS 구독/결제 FE — Dentbird Account

크레딧 기반에서 구독제로 전환하는 결제·권한 도메인의 프론트엔드를 전담 설계·구축했습니다. 플랜·시트 구매, 구독 취소/재개, 쿠폰, 결제수단까지 결제 워크플로우 전체를 구현하고, 금액이 어긋나기 쉬운 흐름의 정확성을 검증과 테스트로 확보했습니다.

- 명령형 방어 코드를 **ErrorBoundary 선언적 처리로 이관**하고, 결제 정보를 못 받아도 핵심 흐름은 살아남도록 Fault Tolerance를 설계했습니다.
- 서버가 내려주는 비즈니스 에러를 커스텀 에러로 코드별 분기하고, FSD 레이어 규칙을 직접 설계했습니다.
- **판단**: FSD·패턴을 과적용해보고 — 폴더 위치 합의 비용, 팀원 이해 분기 — "기술 도입은 우선순위 높은 문제부터"라는 기준을 확립했습니다.
