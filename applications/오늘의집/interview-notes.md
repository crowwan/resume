## JD 미달 항목과 답변 프레임

### SSR / BFF (FE 공통 자격에 가까움)
- **현 상태**: 실무로 SSR 운영·BFF 설계를 깊게 해본 경험은 없음.
- **인접 근거**: 기업 랜딩을 **Next.js 13(Pages Router) 풀스택**으로 화면+서버 API(Fastify)까지 다뤘고, 제품에서 **런타임 환경 분리·번들 구조·빌드 성능**은 직접 맡음.
- **답변 방향**: "서버사이드 JS 런타임과 풀스택 데이터 흐름은 다뤄봤고, SSR/BFF는 그 연장선이라 빠르게 채울 자신이 있다. 다만 대규모 트래픽에서의 SSR 운영은 입사 후 우선 학습 영역."

### Core Web Vitals / 대규모 웹 트래픽 성능 (우대)
- **현 상태**: 본인 성능 강점은 빌드/인프라·렌더링이지, **대규모 소비자 트래픽 CWV 최적화는 미경험**. → "성능 일괄 개선" 류 주장 금지.
- **인접 근거**: 랜딩에서 **LCP·폰트 preload, 이미지 최적화, 정적 자원 캐시, Lighthouse 측정**. 케이스 목록 **썸네일 지연 로딩·요청 배치**.
- ⚠️ **Lighthouse 점수 주의**: 개선 전=dev 배포 / 후=localhost라 **환경이 달라 성능 점수 직접 비교 불가**. 구두로 언급 시 "메인 82→93 봤지만 환경차가 있어 단정 못 한다"까지 함께. **SEO 거의 전 페이지 100점은 일관된 사실.**

### 접근성(a11y)
- **현 상태**: findings 전체에서 a11y 기록 0건. **솔직히 실무 경험 없음.**
- **답변 방향**: 지어내지 말 것. "사용자 대면 웹을 해왔지만 접근성은 체계적으로 다뤄본 적 없어, 입사 후 우선 채우고 싶은 영역" — 정직하게.

### LLM 기반 사용자 인터랙션 설계 (Content 직무 고유 책임)
- **현 상태**: 사용자 대면 LLM UX는 직접 해본 적 없음.
- **인접 근거**: 변경 감지·테스트 선별처럼 **AI를 개발 파이프라인의 "판단 단계"에 결합**해 본 경험 + 그 한계(AI가 통과시킨 잘못된 테스트)까지 설계해 본 경험.
- **답변 방향**: "AI를 도구가 아니라 판단 단계에 넣고, 그게 맥락 없이 틀릴 수 있다는 것까지 설계해봤다. 그 감각을 사용자 대면 인터랙션으로 확장하는 데 관심이 크다."

## 원본 자백 문단 (이전 서류 버전에서 이동)

> 대규모 웹 트래픽 환경의 Core Web Vitals 최적화, SSR, BFF, 접근성은 아직 실무 경험이 깊지 않습니다. Next.js 기반 풀스택으로 서버사이드 JS 런타임을 다뤄봤고 제품에서 런타임 환경 분리·번들 구조·빌드 성능은 직접 맡아 왔지만, 사용자 규모가 큰 웹 런타임 성능과 접근성은 입사 후 우선 채우고 싶은 영역입니다.
>
> LLM 기반 사용자 인터랙션 설계는 직접 해본 적이 없습니다. 다만 변경 감지·테스트 선별처럼 AI를 개발 파이프라인의 판단 단계에 결합해 본 경험이 있어, 그 감각을 사용자 대면 인터랙션으로 확장하는 데 관심이 큽니다.

## 도메인 미스매치 인식 (전략 메모)

- Content 직무 핵심 책임 = 대규모 사용자 대면 콘텐츠·커뮤니티 웹. 본인 경력은 B2B SaaS·치과 CAD/CAM이라 **도메인 거리감이 있음**(서류 1차 탈락의 큰 요인으로 추정).
- 강점이 더 정확히 맞는 팀 = **Client Foundation**(플랫폼·공통기반). 재지원·다른 팀 지원 시 고려.
- 그럼에도 Content로 간다면: 랜딩(사용자 대면 웹)·썸네일(성능)을 전면에, 미달 영역은 위 프레임으로 정직하게.
