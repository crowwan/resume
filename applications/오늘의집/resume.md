## 자기소개

2023.09부터 AI 기반 치과 CAD/CAM SaaS(DentBird)에서 화면 구현을 넘어 **제품의 구조와 품질을 책임지는** 프론트엔드 개발자로 일해왔습니다. 회귀를 사람이 매번 확인하던 환경에 E2E·격리 재현·AI 변경 감지로 자동화된 안전망을 0→1로 깔았고, 분산된 앱을 모노레포로 통합하며 거대해진 코드의 모듈 경계를 다시 그었습니다. "대충 넘어가지 않는" 품질과 빠른 실행을 동시에 추구하는 팀에서 제 강점이 가장 잘 맞는다고 생각합니다.

- **품질 자동화** — 테스트가 없던 제품에 E2E·격리 재현·AI 변경 감지 테스트 인프라를 구축해 릴리스 신뢰성을 끌어올립니다.
- **구조** — 분산된 앱을 NX 모노레포로 통합하고, 공통 모듈을 Micro Frontend로, 환경 설정을 런타임으로 분리합니다.
- **판단** — 기술 결정을 여러 대안과 비교하고, 빠르게 도입했다가 한계를 만나면 근거를 갖고 재설계합니다.
- **범위** — FE를 중심으로 Electron 데스크톱·빌드 인프라·일부 백엔드까지 제품의 처음부터 끝까지 다룹니다.

## 프로젝트

### 1. 품질 자동화 — 테스트 인프라 0→1 *(품질 자동화·CI/CD)*

테스트가 거의 없던 제품에서, 회귀를 사람이 매번 확인하다 놓치는 일이 잦았습니다. "테스트를 더 짜는" 대신 **재현 가능한 환경과 자동 선별 실행**으로 품질을 자동화했습니다.

- 특정 커밋 시점의 클라이언트+서버를 **Docker로 재현하는 격리 환경을 주도 구축**하고, qa/prod 데이터를 복제해 즉시 재현하도록 만들어 환경 차이로 깨지던 디버깅·E2E를 안정화했습니다.
- Playwright 기반 E2E 프레임워크를 주도 구축하며, 반복되던 로그인 셋업 코드를 공통 Page Object로 대체해 **중복을 93% 제거**하고, 세션 공유로 스위트 실행 시간을 **18분 → 11분(39%↓)** 단축했습니다.
- EC2에 Claude를 띄워 커밋 변경(diff)을 분석하고 **변경과 관련된 E2E만 자동 선별·실행**해 Teams로 보고하는 AI 변경 감지 시스템을 구축해, 회귀를 같은 PR 안에서 조기에 잡도록 했습니다.
- GitHub Actions self-hosted 러너 기반 빌드 파이프라인을 이관·재설계해 빌드 시간을 **20분 → 6분(직접 비교)** 으로 줄였습니다.

### 2. 플랫폼 아키텍처 — 모노레포 통합 & Micro Frontend *(구조·판단)*

분산돼 있던 여러 프론트엔드 앱을 NX 모노레포로 통합하고, 4개 서비스가 공유하는 공통 기능을 모듈화하며 **거대해진 코드의 모듈 경계를 다시 그었습니다.**

- 공통 기능을 라이브러리로 배포했더니 각 서비스가 버전 업·재배포를 반복해야 해서, **iframe + postMessage 런타임 통합**으로 전환했습니다. Module Federation은 직접 도입해본 뒤 모노레포 밖 소비처의 설정 부담을 이유로 이 건에선 제외하고, console-client에는 별도로 적용했습니다.
- 모노레포 통합 후 빌드타임 통합으로 옮겼다가 **통합 배포가 실제로는 잘 이뤄지지 않고 배포 부담이 커지자 다시 iframe 런타임 통합으로 회귀**하며, "통합 전략에 정답 기술은 없고 조직·배포 제약에 맞는 선택이 있을 뿐"임을 체득했습니다.
- 레거시 모노레포 통합 시 **TypeScript 에러 688 → 0**, Facade 패턴으로 토큰 관리 코드 **200 → 33줄(85%↓)** 로 정리했습니다.

### 3. DentBird Account — B2B SaaS 구독/결제 FE *(제품 도메인)*

회사가 일회성 크레딧 판매에서 반복 구독 매출로 비즈니스 모델을 전환하는 결제·권한 도메인의 프론트엔드를 전담 설계·구축했습니다.

- 플랜 업그레이드·시트 구매·구독 취소/재개·쿠폰·결제수단까지 결제 워크플로우 전체를 구현하고, 일할 계산·구독 변경처럼 **금액이 어긋나기 쉬운 흐름의 정확성**을 클라이언트 검증과 단위 테스트로 확보했습니다.
- 한 기능의 오류가 전체 페이지를 멈추던 구조를 ErrorBoundary 기반 선언적 에러 처리로 기능 단위로 격리했습니다.
- FSD·디자인 패턴을 적극 도입해본 뒤 **"기술 도입은 우선순위 높은 문제 해결이 먼저"** 라는 원칙을 얻었습니다 — 패턴이 푸는 문제를 정확히 이해하지 못한 채 일관성을 명분으로 도입했던 한계를 돌아본 결과입니다.

### 4. Electron 데스크톱 & 빌드 인프라 *(범위)*

웹과 로컬 CAM 소프트웨어를 잇는 Electron 앱을 0→1로 설계하고, Chrome LNA 규제에 대응해 여러 통신 방안을 비교한 뒤 장기 안정성 기준으로 Custom Protocol을 채택했습니다. 12종 CAM 소프트웨어를 좌표 변환으로 연동하고, 빌드·배포 인프라를 self-hosted 파이프라인으로 재설계했습니다.

## 보완하고 싶은 영역 (정직하게)

대규모 웹 트래픽 환경의 **SSR·BFF·접근성(a11y)·Core Web Vitals 최적화**는 아직 실무 경험이 깊지 않습니다. Next.js 기반 풀스택(랜딩 페이지 + Fastify 서버 API)을 직접 개발해 서버사이드 JS 런타임은 다뤄봤고, SaaS 제품에서 런타임 환경 분리·번들 구조·빌드 성능도 다뤄왔지만, 사용자 규모가 큰 웹 런타임 성능과 접근성은 입사 후 빠르게 채우고 싶은 영역입니다.
