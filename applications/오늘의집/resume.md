## 프로젝트

### 1. 품질 자동화 — 테스트 인프라 구축

테스트가 거의 없던 제품에서, 회귀를 사람이 매번 확인하다 놓치는 일이 잦았습니다. "테스트를 더 짜는" 대신 **재현 가능한 환경과 자동 선별 실행**으로 품질을 자동화했습니다.

- 커밋 시점의 클라이언트+서버를 **Docker로 격리 재현**, 상태 보존 서비스 공유로 셋업을 32분 → 3~5분으로 단축
- 흩어진 E2E를 모노레포로 통합, Page Object·세션 자동 관리로 반복 로그인 셋업을 제거
- **AI 변경 감지 E2E**: EC2 Claude가 커밋 변경을 분석해 관련 E2E만 선별·실행하고 결과를 Teams로 보고 → 회귀를 같은 PR 안에서 조기 탐지
- GitHub Actions self-hosted 러너 기반 빌드 파이프라인을 재설계해 빌드를 20분대 → 6분으로 단축
- **판단**: "격리하기 쉬운 환경"을 먼저 깔아 그 위에 자동화를 확장. AI 변경 감지는 운영 한계(보안·안정성)까지 겪고 재편 중

### 2. 플랫폼 아키텍처 — 모노레포 통합 & Micro Frontend

분산돼 있던 여러 프론트엔드 앱을 NX 모노레포로 통합하고, 4개 서비스가 공유하는 공통 기능(설정·내보내기·탐색기·뷰어)을 모듈화하며 **거대해진 코드의 모듈 경계를 다시 그었습니다.**

- 공통 기능 변경을 **각 서비스 반복 수정에서 모듈 한 곳 수정으로** 좁힘 — iframe 런타임 통합
- Module Federation은 직접 도입해본 뒤 모노레포 밖 소비처의 설정 부담으로 이 건엔 제외, 다른 서비스엔 적용
- 사내 3D 라이브러리→Three.js 전환(팀 주도)에서 **Viewer 렌더링 정합·회귀 수정을 담당** *(현재 진행)*
- **판단**: 빌드타임 통합 → 배포 부담 증가 → 다시 iframe 회귀. "정답 기술 없이 조직·배포 제약에 맞춰 재선택"

### 3. B2B SaaS 구독/결제 FE — Dentbird Account

회사가 일회성 크레딧 판매에서 반복 구독 매출로 비즈니스 모델을 전환하는 결제·권한 도메인의 프론트엔드를 전담 설계·구축했습니다.

- 플랜·시트·취소/재개·쿠폰·결제수단까지 **구독 워크플로우 전체 구현**
- 한 기능의 오류가 전체 페이지를 멈추던 구조를 **ErrorBoundary 선언적 처리로 이관**하고, 결제 정보를 못 받아도 핵심 흐름은 살아남도록 Fault Tolerance 설계
- 서버 비즈니스 에러를 커스텀 에러 클래스로 코드별 분기, FSD 레이어 규칙 직접 설계
- **판단**: FSD·패턴을 과적용해보고 "기술 도입은 우선순위 높은 문제부터"라는 기준 확립

### 4. Electron 데스크톱 & 빌드 인프라

웹과 로컬 CAM 소프트웨어를 잇는 Electron 앱을 설계·구축하고, Chrome LNA 규제에 대응해 여러 통신 방안을 비교한 뒤 장기 안정성 기준으로 Custom Protocol을 채택했습니다.

- 브라우저-로컬 통신을 **Custom Protocol 중간 레이어로 우회**하도록 재설계 — 기존 로컬 서버 방식을 걷어냄
- 이질적인 외부 CAM들의 좌표계·전달 방식 차이를 **하나의 변환·연동 인터페이스로 추상화**
- Batch·Linker 공통 빌드 인프라를 self-hosted로 재설계해 빌드를 20분대 → 6분으로 *(팀 작업, 본인 최다 기여)*
- **판단**: AI로 LNA 우회 20여 방안을 탐색해 장기 안정성 기준으로 Custom Protocol 채택. WebSocket은 곧 LNA 적용 대상이라 재차단 우려로 탈락

## 보완하고 싶은 영역 (정직하게)

대규모 웹 트래픽 환경의 **SSR·BFF·접근성(a11y)·Core Web Vitals 최적화**는 아직 실무 경험이 깊지 않습니다. Next.js 기반 풀스택(랜딩 페이지 + Fastify 서버 API)을 직접 개발해 서버사이드 JS 런타임은 다뤄봤고, SaaS 제품에서 런타임 환경 분리·번들 구조·빌드 성능도 다뤄왔지만, 사용자 규모가 큰 웹 런타임 성능과 접근성은 입사 후 빠르게 채우고 싶은 영역입니다.

**LLM 기반 사용자 인터랙션** 설계는 아직 직접 해보지 못했지만, AI를 개발 파이프라인의 판단 단계(변경 감지·테스트 선별)에 결합해본 감각을, 사용자 대면 인터랙션 쪽으로 확장하는 데 관심이 큽니다.
