자기소개

2023년 9월부터 AI 기반 치과 CAD/CAM SaaS인 Dentbird에서 프론트엔드 개발자로 일하며, 웹에서 만든 데이터를 사용자 PC의 외부 소프트웨어로 넘기는 Electron 연동 앱을 설계·단독 운영해 왔습니다. 토스플레이스 POS도 웹뷰가 맡는 UI·비즈니스 로직과 네이티브가 맡는 하드웨어·결제 연동을 잇는 같은 계열의 문제라고 봅니다. 브라우저 보안 정책에 막힌 연동을 재설계하고, 좌표·전달 방식이 제각각인 외부 장비 12종을 단일 인터페이스로 통합한 경험이 직접 닿는다고 생각했습니다. 화면 구현뿐 아니라 모노레포·빌드·배포까지 담당해 왔습니다.

주요 프로젝트

각 프로젝트의 배경·대안 비교·회고는 포트폴리오에 정리했습니다.

웹·로컬 CAM 연동 Electron 앱 (Dentbird Linker)

웹 보철 케이스를 사용자 PC의 CAM 소프트웨어로 전달하는 사내 연동 앱을 단독 설계·운영하며, 좌표계·전달 방식이 제각각인 외부 CAM 12종을 단일 연동 인터페이스로 통합했습니다.

  • Chrome LNA 정책으로 막힌 로컬 서버 통신을, 장기 안정성 기준의 대안 비교 끝에 Custom Protocol 중간 레이어로 재설계
  • 좌표계·파일 전달 방식이 제각각인 외부 CAM 12종을 단일 변환·연동 인터페이스로 통합
  • 명세 없던 기존 CAM 연동을 특성화 테스트로 고정한 뒤 재구현
  • 설치 감지는 틀려도 사용자가 막히지 않게 비차단 안내로 통일하고, CAM 없이 시나리오를 재현하는 Mock Server와 Datadog 로그로 검증·진단
  • Windows 전용 CAM을 Mac에서 실제 전송과 동일하게 재현하는 원격 검증 도구를 직접 만들어 팀 스킬로 등록 — 조건을 하나씩만 바꿔 대조해 형상 오류의 원인을 규명하고, 다른 사례는 벤더 실행 인자 제약임을 확인해 결함이 아님을 확정

Medit 소프트웨어 연동 인앱 현대화

협력사 Medit의 소프트웨어 안에서 Dentbird를 쓰도록 제공한 Electron 인앱이 2023년 이후 방치돼 곧 서비스 사용이 끊길 상황이었고, 엔진·로그인·회사 라이브러리 의존을 정리해 되살리면서 우리 서비스가 바뀌어도 재빌드가 거의 필요 없는 구조로 전환했습니다.

  • 곧 배포될 우리 서비스 버전에서 인앱이 서비스를 아예 사용할 수 없게 될 상황을, 최신 3D 엔진이 요구하는 WASM 기능(JSPI) 구동을 위해 Electron 25에서 31로 업그레이드해 해소
  • 로그인 후 엉뚱한 페이지로 이동하고 미로그인 상태에서 작업이 저장되지 않던 문제를, 우리 서비스 내부 응답에 기대던 로그인 감지를 IPC 기반으로 재설계해 해결
  • 우리 서비스가 바뀔 때마다 인앱이 함께 어긋나던 원인이 불필요한 내부 결합임을 확인, 회사 UI 라이브러리 의존을 MUI로 대체하고 결합을 최소화해 재빌드 필요 자체를 축소
  • 브라우저 stub 검증이 불안정해 실제 Electron 환경에 CDP로 붙어 3D 엔진 구동까지 확인 (배포 대기, 릴리스는 협력사 Medit 담당)

B2B 구독·결제 시스템 프론트엔드

일회성 크레딧에서 반복 구독으로 전환하는 시점에 글로벌 멀티테넌트 결제·권한 프론트엔드를 전담하고, 모든 에러를 unknown으로 처리하던 구조를 예측 가능/불가능으로 나눠 한 기능의 실패가 전체 페이지를 멈추지 않도록 개선했습니다.

  • 플랜 업그레이드·시트 구매·구독 취소·재개·쿠폰·결제수단·결제 히스토리까지 구독 워크플로우 전체를 구현
  • 결제 상태를 서버·Stripe 동기화 기준으로 두고, 무한 반복 방지 폴링·origin 격리된 결제 팝업으로 외부 연동 복원력 확보
  • 모든 에러를 unknown으로 일괄 처리하던 것을 예측 가능/불가능으로 구분 — 비즈니스 에러는 코드별 분기, 시스템 실패는 ErrorBoundary로 격리하고, 이 문제의식을 이후 5개 앱 관측·복원력 표준화로 확장

프론트엔드 모노레포 통합

별도 레포의 클라이언트 앱 2종·공용 라이브러리 6종을 커밋 이력을 보존하며 단일 NX 모노레포로 통합하고, 환경·도메인 구성을 일원화했습니다.

  • 환경별 도메인·URL 구성을 단일 통합 라이브러리로 일원화 — 팀의 런타임 환경 분리·격리 재현이 이를 기반으로 동작
  • 별도 레포 클라이언트 앱 2종·공용 라이브러리 6종을 Git Subtree로 이관
  • NX 자동 타겟 추론이 일으키던 메모리 부족 빌드 실패를 진단, 불필요한 산출물 설정을 제거해 해소

격리 재현 환경과 AI 변경 감지

테스트가 거의 없던 제품에 격리 재현 기반의 자동 회귀 감지 체계를 구축하고, 배포마다 검증을 통과해 나간 결함을 추적하는 회귀 측정(CFR) 대시보드까지 직접 만들어 팀에서 운영하고 있습니다.

  • 커밋 시점 클라이언트·서버·DB를 하나의 컨테이너로 통합해 결정론적 격리 재현 환경 구성
  • 백오피스 전 영역에 E2E를 구축하며 로그인 중복을 공통 헬퍼로 약 93% 감소, 여러 레포에 나뉜 Playwright E2E를 모노레포로 통합·Page Object 리팩토링으로 중복 제거
  • 커밋 변경을 분석해 연관 QA 테스트 케이스만 자동 선별·실행하고, 실패를 실제 회귀와 테스트 코드 문제로 1차 분류해 Teams로 보고하는 AI 변경 감지를 EC2에 구축(10분 간격 크론잡 자동 실행)
  • 개발팀 공용 도구로, 품질 테스트 케이스(TC)가 E2E로 검증됐는지 추적하는 대시보드를 구축하고 E2E 통과 결과가 자동 반영되도록 연동 (FE 화면 + API)
