# Interviews — 4축 인터뷰 원본 보관소

이 디렉토리는 각 프로젝트의 **4축 인터뷰 원본 Q&A**를 보존하는 곳입니다.
`career-description.md`의 압축본이 잃어버리는 디테일을 여기서 끝까지 보관해, **면접 답변 스크립트로 재활용**합니다.

> 이력서 작업 = 면접 준비. 본문은 채용 담당자용, 이 디렉토리는 면접관용.

## 인터뷰 진행 룰 (Claude용)

1. **한 번에 한 프로젝트, 한 번에 한두 질문씩.**
   - 질문을 쏟아내지 마세요. 답이 깊어질 시간을 주세요.

2. **표면 답에서 멈추지 마세요.**
   - 사용자가 "X를 도입해서 좋아졌어요" 정도로 답하면 → "구체적으로 뭐가 좋아졌나요? 누가 효과를 봤나요? 지금도 유지되나요?" 한 겹 더.
   - 기준: 브리핑의 MFE iframe 예시 수준의 집요함.

3. **답을 그대로 기록하세요.**
   - Claude가 "정리한 표현"으로 옮기지 말 것. 면접에서 사용자가 실제로 쓸 단어가 그대로 남아야 합니다.
   - 단, 너무 긴 답은 4축 헤더 아래로 분리 정리(원문 보존 + 헤더 구조).

4. **모르는 건 모른다고 적으세요.**
   - "수치 기억 안 남" → 그대로 기록. 본문에는 정량 대신 정성으로 변환.
   - **추정/창작 절대 금지.**

5. **인터뷰가 끝나면 본문 반영 단계로.**
   - 같은 PR에서 `interviews/0X-*.md` 갱신 + `career-description.md` 압축 + `resume.md` 키워드 정렬을 함께 처리.

## 면접 답변 스크립트 변환 가이드

본문(career)은 **읽는 문서**, 면접 답변은 **말하는 문서**. 다음 변환 규칙을 따릅니다.

| 본문 표현 | 면접 답변 표현 |
|-----------|---------------|
| "Module Federation으로 전환했습니다." | "원래 iframe으로 5개 모듈을 굴렸는데, 도메인 5개·SSL 5개·빌드 파이프라인 5개를 따로 관리해야 했어요. 그게 정말 부담이라서 Module Federation으로 갔습니다." |
| "TS 에러 688→0개 해결" | "마이그레이션 직후 TS 에러가 688개였는데, ~~ 방식으로 ~~까지 줄여 0개로 만들었습니다. 핵심은 ~~였어요." |
| "Page Object 패턴 적용" | "처음엔 로그인 코드가 테스트마다 중복됐어요. ~~ 시점에 ~~ 이유로 Page Object로 묶었고, 로그인 코드가 93% 줄었습니다." |

핵심:
- **숫자 앞에 "왜 그 숫자였는지" 한 문장**을 붙입니다.
- **사람이 어떻게 아팠는지**부터 시작합니다 (HR도 이해할 수 있게).
- **지금 어떤가**로 마무리합니다 (지속성/한계).

## 인터뷰 완료 후 체크

- [ ] 사용자 답을 Claude 표현으로 변형하지 않았나
- [ ] 모르는 사실/수치를 추정해 채워 넣지 않았나
- [ ] 면접 답변 스크립트가 작성됐나
- [ ] `career-description.md` 해당 섹션이 새 서사로 압축됐나
- [ ] `resume.md` 해당 카드가 가장 강한 1~2줄로 정렬됐나
- [ ] Status가 `done`으로 갱신됐나
