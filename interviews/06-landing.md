## 1. WHY — 문제 실체

**Q1. v3 전면 리뉴얼을 인턴 입사 직후 맡았는데 — ① 기존(구버전) 랜딩에 뭐가 문제여서 갈아엎은 건가요? ② 그 큰 작업을 신입/인턴인 본인이 주도하게 된 경위는요?**

> **디자인 개편이 주 목적이었고 다국어 대응도 같이 필요했다. 비교적 큰 작업이라기보다는 회사의 업무 프로세스와 작업 방식 등을 익히기 위한 규모 정도였다.**

**해석 (카드 위상 결정):**
- 랜딩 메인 = **신입 온보딩 성격**. 전략적 임팩트 작업 아님 → **과대포장 금지**
- 서사 방향: "입사 첫 업무를 빠르게 익혀 혼자 완성 → 3개월차 BO 1주 풀스택" = **빠른 적응력·자기주도 성장**
- 카드 하이라이트 = 메인 리뉴얼 ❌ / **BO 3계층 풀스택 ✅**

---

## 2. HOW — 트레이드오프

**Q2. 랜딩 메인에서 본인이 직접 방법을 찾아 해결한 기술 결정이 있나요? (i18n 타입세이프 / AOS 버그 / useI18nStyle)**

> **i18n 타입세이프는 내가 찾아서 도입했다.** (`i18next-resources-for-ts` 자동 타입 생성)

**Q2-후속. 왜 도입했나? (도입 전 불편)**

> **i18n 키를 잘못 사용해서 UI에 키값이 그대로 보여지는 문제가 종종 있었다.** 기존엔 런타임에야 발견됐는데, i18n 타입 추가로 **컴파일 단계에서 잘못된 키/없는 값을 개발자가 미리 알 수 있게** 하고 싶었다.

**→ 문제→해결 서사 (확정):**
- 문제: 번역 키 오타 → **UI에 raw 키 노출** (런타임에야 발견되는 사용자 눈에 보이는 버그)
- 해결: `i18next-resources-for-ts` 타입 생성 → **컴파일 타임에 잘못된/없는 키 사전 차단**
- = 랜딩 메인의 기술 하이라이트 (신입의 자기주도 도구 탐색)

---

## 3. RESULT — 결과 (i18n 타입세이프 기준)

> **구조는 유지됨. 단 "키 노출 버그 감소" 효과 체감은 불명 — 정직하게 미상.**
>
> ⚠️ **FOLLOW-UP (사용자 요청)**: 효과를 체감 못 한 이유를 나중에 회고해 추가 정리. → 본문엔 효과 수치 없이 **"컴파일 타임에 잘못된 i18n 키를 검증하는 구조 도입"** 까지만 쓴다.

## ▶ BO 3계층 조직관리 풀스택 — 4축

> 입사 3개월차 / 2023-12-07~13 1주 / FE 53커밋 + 서버 PATCH API.

**BO-Q1. 어떻게 맡았나 / 왜 1주에 가능했나?**

> **내가 제안한 건 아니고 직접 맡아서 했다. 단순 CRUD라 빨랐다.**

**해석 (위상 재조정 — 중요):**
- "1주 53커밋"은 기술 성취가 아니라 **단순 CRUD를 빠르게** 처리한 것 → **과대포장 금지** (면접에서 "단순 CRUD 아니냐"에 무너짐)
- 살릴 가치 = **신입이 FE+서버 동시 풀스택**으로 처리 + 처리 속도
- **랜딩 카드 전체 위상**: 메인 카드 ❌ / **"신입 초기 온보딩 + 자기주도 개선(i18n 타입세이프) + 풀스택 노출"** = 가벼운 카드
- → **career 6번(현재 6-1~6-8, 8개 서브섹션) 대폭 축소 대상**

## 면접 답변 스크립트 (2~3분)

> 랜딩 = 가벼운 카드. i18n 타입 안정성 결정 서사 + 풀스택 경험 중심. **과대포장 금지.**

"제 입사 첫 업무가 회사 랜딩 페이지 v3 리뉴얼이었어요. 디자인 개편이랑 다국어 대응이 주 목적이었고, 회사 프로세스를 익히는 온보딩 성격이었습니다. 구버전은 입사 전에 만들어져 있었고, v3는 제가 거의 단독으로 했어요.

여기서 제가 직접 개선한 건 i18n입니다. 초기에 번역 키를 잘못 쓰면 UI에 키값이 그대로 노출되는 버그가 종종 있었는데, 런타임에야 발견되니까 불편했어요. 그래서 `i18next-resources-for-ts`를 찾아서 도입했습니다. 번역 리소스에서 타입을 자동 생성해, 없는 키를 쓰면 컴파일 단계에서 바로 잡히게 했어요.

3개월차엔 회사 소개 페이지의 조직 관리 백오피스를 맡아, Groups-Teams-Members 3계층 CRUD를 프론트엔드부터 서버 PATCH API까지 직접 만들었습니다. 단순 CRUD였지만 프론트와 백엔드를 동시에 다뤄본 첫 경험이었어요.

성능은 LCP·폰트 preload, 이미지 최적화, 캐시 설정 같은 기법을 적용했습니다."

**꼬리질문 대비:**

- 성능 점수? → "dev와 localhost라 환경이 달라 점수 직접 비교는 안 했고, 기법 적용에 집중했다"
